# Кинотеатр+

## 1. Введение

### 1.1 Наименование программы  
**«Кинотеатр+»**

### 1.2 Краткая характеристика области применения  
Система **«Кинотеатр+»** предназначена для организации продажи билетов в кинотеатрах с несколькими залами.  
Для каждого зала предусмотрен **один оператор-кассир**, который выполняет продажу и возврат билетов.

## 3. Назначение разработки

Система используется **двумя типами пользователей:**
-  **Посетитель**
-  **Оператор-кассир**

### 3.1 Функциональное назначение

**Посетитель может:**
- просматривать расписание фильмов;
- видеть заполненность зала (свободные и занятые места).

**Оператор-кассир может:**
- выполнять функции посетителя;
- помечать места как «занятые» или «свободные»;
- редактировать сеансы (добавлять, удалять, изменять).

### 3.2 Эксплуатационное назначение  
- Режим «посетитель» может отображаться на больших мониторах.  
- Режим «кассир» запускается на рабочем месте оператора.

---

## 4. Требования к программе

### 4.1 Функциональные требования

#### 4.1.1 Основной функционал

**Авторизация:**
- 2 типа пользователей — *кассир* и *посетитель*.

**Посетитель может:**
- Просматривать расписание.
- Смотреть заполненность зала.

**Расписание включает:**
- дату и время;
- название фильма;
- возрастные ограничения.

**Схема зала содержит:**
- экран;
- ряды и места;
-  свободные места,  занятые места.

**Оператор-кассир может:**
- выбирать несколько мест (Ctrl + мышь);
- помечать места как занятые/свободные;
- добавлять и удалять сеансы;
- изменять данные через двойной клик.

После завершения сеанса он автоматически исчезает из списка.  
Изменения кассира отображаются у посетителей не позднее **5 секунд**.

---

### 4.1.2 Ввод и хранение данных

| Параметр | Требование |
|----------|------------|
| Дата и время | `ДД.ММ.ГГГГ ЧЧ:ММ` |
| Название фильма | ≤ 200 символов |
| Возрастные ограничения | Формат «+» |
| Хранение данных | В базе данных |

---

### 4.1.3 Временные характеристики  
- Обновление данных: **≤ 5 секунд после изменения кассиром**

---

### 4.2 Надёжность

- Вероятность безотказной работы: **≥ 99.99%**
- Резервное копирование данных (замещением)

**Время восстановления после отказа:**
| Тип отказа | Время восстановления |
|------------|------------------------|
| Сбой питания / ОС | ≤ 10 минут |
| Поломка оборудования | После ремонта и переустановки ПО |

---

### 4.3 Условия эксплуатации

- Клиент запускается на ПК кассира и посетителя.
- База данных — на отдельном сервере.
- Программа работает **во весь экран**.
- **Закрыть, свернуть, запустить другое ПО нельзя.**
- Программа стартует автоматически при запуске ОС.

---

### 4.3.1 Климатические условия  
Не требуются.

### 4.3.2 Обслуживание  
Не требуется.

### 4.3.3 Персонал  
| Роль | Требования |
|------|------------|
| Системный администратор | Высшее образование, настройка СУБД, сети |
| Оператор-кассир | Навыки работы с ПК |
| Посетитель | Не требует подготовки |

---

### 4.4 Технические требования

| Устройство | Минимальные требования |
|------------|--------------------------|
| ПК кассира | CPU ≥ 1 ГГц, RAM ≥ 1 ГБ |
| ПК посетителя | CPU ≥ 1 ГГц, RAM ≥ 1 ГБ |
| Сервер БД (основной + резервный) | CPU ≥ 1 ГГц, RAM ≥ 1 ГБ |

---

### 4.5 Совместимость

- Соединение клиента и БД — по локальной сети, **HTTP**  
- Посторонние устройства в сети — исключены

---

### 4.6 Маркировка и упаковка  
ПО передаётся через Internet в виде архива.  
Проверка подлинности — по контрольным суммам.

---

### 4.7 Транспортировка и хранение  
Специальных условий не требуется.

---

### 4.8 Специальные требования
